# Eurogame Engine Lab · 德式卡牌桌游引擎

以《方舟动物园》双人基础版为中期目标的独立规则引擎与浏览器测试工作台。

**当前方舟已进入阶段三可玩版，仍不等同于完整基础版。** 支持双人地图 A / 0、起手八选四、五行动、三种特殊馆、一次性动物转移、20 张牌库保护项目、随机保护奖励、双重行动、协会、休息和终局，并配备简单 AI、存档和回放。原创样例「植序工坊」仍支持 2–4 人六轮对局。

## 启动

需要 Node.js 24、pnpm 10。依赖版本与 `pnpm-lock.yaml` 一起锁定。

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

打开终端显示的地址，项目基础路径为 `/eurogame-card-engine/`。页面使用 hash 路由，刷新子页面不需要服务器重写。

```powershell
pnpm check
pnpm simulate --seeds 100 --strategy random
pnpm simulate --seeds 100 --strategy heuristic
pnpm simulate --seeds 100 --strategy heuristic --players 4
pnpm simulate:ark --seeds 20
pnpm simulate:ark --seeds 20 --map 0 --output .artifacts/ark-simulation-map0
pnpm exec playwright install chromium
pnpm test:e2e
```

`test:e2e` 测试构建结果，先执行 `pnpm build`。模拟报告在 `.artifacts/simulation/summary.json`；失败或截断案例附带可回放档案。

## 工作台

- **创建对局**：默认入口 `#/lobby`，先选游戏、AI 模式与总人数。Demo 支持 2–4 人；方舟可选择双人地图 A 或空白起步的地图 0。在线匹配暂未开放。两款游戏分槽保存，互不覆盖，可从创建页继续。
- **方舟对局**：选择方舟后创建双人 AI 对局，或打开 `#/ark` 继续。规则说明位于 `#/ark-rules`，进度页区分首版实现与完整基础版目标。
- **游戏规则**：独立页面 `#/rules` 说明起始资源、三个行动、卡牌结算、每轮收入、终局和获胜条件。牌桌也有直达入口。
- **对局工作台**：12 种原创卡、24 个实例，每位玩家各 3 张起始手牌、5 资金、1 能量、0 得分，公共展示区 4 张。每人每轮一次行动，六轮结束，得分最高者获胜，平分并列。
- **经营**：资金 +2、能量 +1；**研究**：最多抽 2 张，牌库不足不重洗；**建设**：从手牌或展示区打出一张牌，展示区额外支付 1 资金。
- 每轮所有玩家行动后结算收入，最后一轮也结算。效果中的选择必须先完成，展示区在整个行动结束时补充。
- **简单 AI**：按自己可见的手牌、资源、公开市场与剩余轮数评估合法行动；考虑得分、资金、能量、收入与抽牌，自动完成连续或嵌套选择。不查看其他玩家手牌、牌库顺序，不连接外部模型。
- **选择与恢复场景**：保证首张手牌为「种子图书馆」，便于测试支付一次、连续选择、刷新恢复。
- **建造交互实验**：自制地图上的旋转、镜像、费用预览、边界和邻接校验，与正式对局分离。
- **方舟规则进度**：分别展示实现数量和规则追踪，完整基础版目标为 235 张。
- **本地参考卡库**：加载本地导入结果查看上游资料；数据不等于可执行规则，不会自动加入牌库。
- **实验工具**：固定种子、终局前场景、历史回放、回退分支和调试资金。回放只读，返回当前对局后继续。

你固定操作 `p1`，其他座位均为 AI，无需换屏或接手确认。AI 思考时人类操作锁定；离开牌桌或进入只读回放暂停 AI，返回后继续。自动存档可恢复 AI 回合与未完成选择；旧同机存档导入后其余座位按 AI 接管。

普通新对局不开启调试；固定牌序等实验场景在实验工具中单独创建。AI 和人类通过相同命令入口提交，命令序列可以重放。完整状态在本机，适用于可信研究环境。JSON 存档包含所有玩家手牌、牌序和完整命令，请与可信测试者共享。

## 参考项目与资料导入

所有外部网站源码集中在 `references/`。保留独立 Git 仓库，不提交为本项目代码或子模块，不运行其安装脚本。

```powershell
git clone --depth 1 https://github.com/Ender-Wiggin2019/Next-Ark-Nova-Cards.git references/Next-Ark-Nova-Cards
pnpm content:import
```

工具使用 TypeScript AST 静态读取基础版数据、关键词、枚举和中英文本，保留上游提交号及 SHA-256。不会 `eval`、动态执行模块或安装参考项目依赖。上游用于估值的函数不执行、不转成游戏效果；关键词只保留标识和描述索引，非有限数字使用显式标记。

结果位于被忽略的 `content/private/ark-nova.reference.json`，可在网页「本地参考卡库」选择该文件。导入结果不改变公开的实现覆盖率。

检出的快照未发现根目录 LICENSE 文件；源码公开不自动构成本站再发行素材的许可。网页使用独立编写的规则逻辑和规范化卡牌数值，不打包 `doc/`、`references/` 或 `content/private/` 的文件、原图或上游网站代码。

本机 Vite 开发与预览服务器可从被忽略的参考项目读取动物与赞助商原图，仅提供严格限定的本地图像接口。静态构建不包含这些图片；参考目录缺失时使用自制卡面与符号，规则功能仍可使用。

## 工程结构

```text
apps/web                 React / Vite 工作台
apps/simulator           无界面对局、策略和复现报告
packages/engine-core     命令事务、版本、随机数、选择队列、回放
packages/mechanisms      资源支付、六角格变换与放置校验
packages/game-demo       原创机制验证游戏
packages/game-ark-nova   方舟专属模块与开发状态
packages/content         公开内容、覆盖矩阵和导入 schema
packages/ui-kit          通用展示组件
content/public           允许公开构建的原创包
content/ark-nova         方舟工程覆盖元数据
content/private          本地资料，Git 忽略
references               外部参考项目，Git 忽略
tools                    内容校验与静态导入工具
```

规则模块不依赖 React、浏览器、时间或网络。所有正式操作通过包含 ID、操作者与修订号的命令提交。非法或异常命令不提交状态；存档导入必须按当前版本重放命令并核对快照。不兼容的原始存档保留，只有主动新建对局才替换。

## GitHub Actions 与 Pages

PR 和 `main` 检查类型、静态规则、内容清单、单元/属性测试、模拟、构建与 Chromium 浏览器操作。只有通过全部检查的 `main` 构建可以部署。报告保留 7 天。

首次发布需要在仓库 **Settings → Pages → Source** 选择 **GitHub Actions**。工作流已准备，尚未代表实际远端发布；推送后在 Actions 查看结果。

构建默认基础路径为 `/eurogame-card-engine/`。其他路径通过 `VITE_BASE_PATH` 指定。测试 URL 和构建路径必须一致。主工作流按仓库名设置发布路径；本仓库名与默认一致。

夜间任务北京时间 02:30 运行 100 个种子，周日使用 1,000 个种子替代。随机对局达到步数上限标记为 `truncated`，不会误报为规则错误；失败案例使任务失败。策略仅用于压力测试，当前统计不能证明平衡性。

方舟另有固定策略的整局回归：PR 使用 3 个种子，夜间使用 20 个。方舟预期必须自然结束，因此异常或截断均使该回归失败，并保存可导入的复现存档。

地图 A、0、1、2 分别执行回归，报告写到 `.artifacts/ark-simulation/`、`.artifacts/ark-simulation-map0/`、`.artifacts/ark-simulation-map1/` 和 `.artifacts/ark-simulation-map2/`。规则版本为 `base-v2-stage-four-1`；旧阶段三及更早存档不会自动转换，导入和本地恢复都会保留原文件并提示不兼容。

发布后检查 HTML 和资源地址。发布前校验失败不触及线上版本；发布后的网络检查失败会标红，需要使用先前保留的 `public-site` 构建手动重新发布。

## 开发路线

详细见 `doc/implementation-plan.md`、`doc/rule-sources.md` 和 `doc/ui-design.md`。

当前覆盖清单为 98 张动物、32 张赞助商、20 张牌库项目、12 种基础保护项目、11 张终局卡，合计 173/235。逐卡人工复核未完成，不将实现数等同于完整基础版验收。

阶段三已补齐地图 0、鸟禽馆／爬行馆及容量、建馆时的一次性转移、20 张牌库项目、动态项目替换、放归、繁育、九选四随机保护奖励和双重行动。双重的两次 X 独立付费，“行动完成后”效果等待两次都完成。

阶段四首批新增地图 1「观测塔」、地图 2「户外营地」、21 张动物和 14 张赞助商。支持调度、叠加双重、挖掘、展示，以及科研／大洲／地形赞助商和新触发组的排序选择。创建页可直接选择四种地图；规则页说明各图特性、边缘奖励与当前覆盖范围。

仍缺 30 张动物、32 张赞助商及其相关的额外行动、群居、毒液／缠绕、部分复杂触发与特殊建筑等机制。标准饲养区占用与特殊馆空间标记是放归和转移的规则依据；户外营地的标准区按有效容量处理。地图中的动物名称是辅助标签，遵循官方不持续追踪每只动物最初位置的处理方式。

验收记录见 `doc/ark-acceptance.md`、`doc/stage-three-acceptance.md`、`doc/stage-four-acceptance.md`。`pnpm ui:capture:ark` 可在本地预览服务运行时生成四张地图与三个桌面尺寸的截图。后续优先补齐未入池卡牌与复杂机制，再进行至少 10 局地图 A/0 人工完整试玩及原作完整基础版验收。
