## 体验方向与风格锚定

交互参考用户本地录屏 `doc/方舟动物园录屏.gif` 与参考项目。核心是稳定的操作位置、就近预览、清楚的合法目标、及时反馈和完整的卡牌信息。延续本项目的米白纸面、森林绿、蓝色水域和紫灰岩石；卡牌类别使用稳定的色带。地图上的建筑保持整块轮廓，贩售亭与岩石有形状、名称和颜色三重区别。

Art Demon King 主文件对本项目的可用经验：

- 风格先锚定，再决定素材；避免地图、图标、卡面各自使用无关风格。
- 把资产当作有版本、命名、规格、来源和审核状态的数据管理。
- UI 的色彩、字体、间距、组件与动效使用统一规范。
- 同时考虑美术可读性和工程开销：复用图集、缓存、预加载、错误回退。
- 验收应有可执行证据，不以截图印象或通过测试数量替代目标本身。

具体调整：桌游工作台需要密集信息，留白比例按可读性和操作路径决定；不机械套用主文件的 40% 留白。正文目标至少 4.5:1，较大文字至少 3:1，关键小字尽量达到 7:1；7:1 属于 WCAG 的更高标准，不能标成普通 AA 的最低要求。动效采用约 150–200ms 的缓出过渡，支持减少动态效果。

## 当前证据与问题

| 现状 | 用户负担或工程风险 | 本轮改进 |
|---|---|---|
| 建造先点格，再到右侧旋转；没有跟随预览 | 需要反复尝试坐标 | 鼠标预览、点击锁定、地图旁旋转／镜像、R/F/Esc |
| 免费建筑用大量坐标按钮选择 | 很难理解实际占地，选择面板可能很长 | 普通建造与免费建造共用地图交互，少量推荐位置保留键盘路径 |
| 卡牌缩略图和固定详情图较小 | 阅读能力需要不断切换注意点 | 悬停／聚焦快速放大，点击继续保留固定详情 |
| 先选卡时只有“请先选择行动卡” | 缺少连贯的下一步 | 详情内可直接开始相应行动，保留所选卡，明确当前步骤 |
| 行动卡重排、资源变动主要是瞬时替换 | 难以看清发生了什么 | 行动槽位过渡、资源变化反馈、简短事件提示；历史回放与减少动态效果单独处理 |
| 小字、浅色说明与资源层级不一致 | 状态和原因不够突出 | 统一设计变量，提升对比度，主操作、状态、次要资料分层 |
| 组件内分散图集坐标、名称和错误处理 | 新增或替换素材容易漏改 | 统一资产定义、图集区域、语义 ID 和类型 |
| 每次挂载请求扁平素材清单；大量重复图片探测节点 | 可能闪烁、重复解码和无意义 DOM | 共享资产加载与错误缓存，按图集预加载一次 |
| 文件名可能包含 placeholder 变体 | 原图可能被占位图覆盖 | 明确、可测试的候选优先级，替代图作为显式变体 |
| 缺少资产规格、大小与来源的可查目录 | 不易排查空白、裁切和公开打包问题 | 资产目录、规格校验、覆盖报告和公开构建审计 |

## 第一阶段：体验与资产管线

### 交互实现

- 统一地图放置模型，支持普通建筑、免费饲养区、姿态奖励和大洲专家奖励。
- 公开玩家视图只给当前选择的合法放置参数，不暴露私有效果队列或对手选项。
- 鼠标悬停仅预览，点击锁定；旋转、镜像和取消预览不提交命令。最终确认仍由规则引擎校验。
- 固定区域显示当前步骤、费用、合法原因和确认按钮；详情可直接开始对应动物／赞助商行动并保留选卡。
- 卡牌快速放大支持鼠标和键盘聚焦，避免覆盖点击目标或泄露隐藏信息。
- 动效只改变呈现，不延迟或重复提交命令；减少动态效果时仍保留文字反馈。
- 桌面尺寸 1366×768、1440×900、1920×1080 的地图、手牌、行动和确认保持同屏。

### 资产管理实现

- 语义 ID 区分卡图、图标、地形、建筑与地标；图集矩形和尺寸集中定义。
- 文件登记来源、使用范围、实际尺寸、字节数、内容哈希和版本 URL。
- 本地参考原图与可公开的内置矢量图分别登记，公开构建只包含发布策略允许的内容。
- 缺少、损坏或不可读取的图像使用统一回退；同一图集失败由共享状态处理。
- 新建资产目录页面，支持检索、分类、查看规格与发布范围，并导出目录诊断 JSON。
- 构建校验检查图集越界、重复 ID、缺失回退、映射数量以及公开产物边界。
