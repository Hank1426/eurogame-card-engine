# 实施计划与验收记录

基线日期：2026-10-30。目标为个人加 AI、每周 10–15 小时、桌面浏览器本地运行的研究工作台。首个原作完整目标为方舟双人、地图 A/0、基础版完整牌库；后续以第二款原创游戏验证引擎复用。

当前入口改为创建页，原创 Demo 支持 2–4 人，方舟阶段四首批支持双人地图 A / 0 / 1 / 2 的限定动物与赞助商牌池。人类固定操作第一个座位，简单 AI 操作其余座位。在线匹配暂未开放。两款游戏分槽保存，均提供规则页、刷新恢复和回放。

## 阶段

| 阶段 | 预算 | 当前交付与剩余工作 |
|---|---:|---|
| P0 资料与规则基线 | 20–30 小时 | 已登记资料来源、公开边界和目标数量；官方版本、FAQ 和卡牌语义仍需逐项人工核对 |
| P1 确定性核心与工作台 | 50–70 小时 | 已提供原创完整对局、命令事务、选择队列、保存恢复、回放、模拟与 CI 配置 |
| P2 五行动与地图切片 | 70–110 小时 | 已实现地图 A / 0、五行动、升级、X、鸟禽馆／爬行馆及一次性转移 |
| P3 双人完整流程 | 100–160 小时 | 已实现限定牌池的协会、动态牌库项目、放归、随机保护奖励、双重、休息、终局和 AI 自然结束 |
| P4 基础牌库与例外 | 160–240 小时 | 首批达到 173/235，新增地图 1/2、调度、叠加双重、挖掘、展示、科研与大洲／地形赞助商；剩余 30 动物／32 赞助商，逐卡人工复核未完成 |
| P5 稳定与验收 | 70–110 小时 | 需 10 局以上人工完整试玩、覆盖地图 A/0、关闭规则与存档问题 |

预算 470–720 小时，加 25% 余量约 590–900 小时；每周 10–15 小时约 9–21 个月。P2 完成后使用实际速度重估。每 2–4 周交付可体验增量，不将“已有字段”当作“规则已实现”。

## 模块契约

游戏模块提供 `createGame`、`getPlayerView`、`getDecision`、`validateCommand`、`applyCommand`、`getResult`，以及输入解析和不变量检查。通用会话负责 ID 去重、修订号、版本、事务提交、回放与分支。

效果队列和待处理选择可序列化。未知效果加载失败。规则核心不读取系统时间、不使用 `Math.random`、不依赖网络。版本指纹用于兼容性判断，不作为密码学认证。

界面只调用命令。玩家视图不暴露牌序、随机数或对手手牌；完整存档为可信调试文件。调试回退及资源变更建立分支。

## 内容与发布

优先级：选定版官方规则和卡牌说明 → 同版 FAQ/勘误 → 已核对的中文稿 → BGA 观察。所有冲突登记解释与来源。

公开包仅使用原创内容。参考项目独立保存在 `references/`；静态导入结果在 `content/private/`。上游代码和素材许可分别确认。来源 commit、文件 SHA-256、类别与原始字段保留，不执行上游估值模型。

完整目标：128 动物、64 赞助商、20 牌库项目、12 基础项目、11 终局卡，共 235 张。行动卡、地图、建筑和奖励另列。每张卡区分已录入、已实现、已测试、已复核；导入不会自动提升覆盖状态。

## 完整方舟验收

- 正常设置后，双人地图 A/0 可以自然进行到终局。
- 所有适用基础规则、235 张卡、互动例外、FAQ 与勘误均可追溯。
- 费用、效果排序、逐张结算、市场补充、休息与终局组合有回归场景。
- 固定整局命令回放一致，待处理选择刷新后不重复付费和发奖。
- 10 局以上人工完整试玩，记录种子、版本、问题和回归案例。
- 无阻断、规则错误或存档损坏；类型、静态检查、规则测试和浏览器检查通过。
- 对外内容通过发行清单；受限内容不进入公共产物和诊断报告。

## 复用与后续

正式方舟验收后另投入 40–80 小时制作 20–40 张卡的第二款原创游戏，使用市场、资源转换、持续效果与固定轮数计分，避免依赖方舟五行动和地图。复用命令、随机数、选择、保存、回放、日志和模拟；核心不出现按游戏名称分支的代码。

当前「植序工坊」是核心的第一份验证样例，不算正式方舟完成后的第二款复用验收。

后续顺序：表格/参数实验 → 方舟更多人数、单人和地图 → 独立服务联机 → 按需求建设编辑器 → 更强策略。异地联机需要权威服务、身份、消息顺序、重连与隐藏信息隔离。
